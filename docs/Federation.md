# Federation transport acceptance

## Scope

Server schema 15 introduces disabled-by-default peer configuration, HTTPS key discovery, independently signed server-key transitions, authenticated diagnostic pings and durable nonce admission. Cross-server message delivery, native session integration, remote user/device discovery and delivery retries remain open. `/versions` therefore does not advertise a federation capability. Transport keys authenticate homeservers, never user encryption identities or group authority.

## Current trust and wire contract

An administrator must configure the local canonical server name, enable federation and allow each remote canonical DNS name. Discovery uses `GET /.well-known/sigil/federation` over HTTPS. The first descriptor is pinned from that explicitly allowed server's certificate-verified connection, unless the operator supplies an expected key fingerprint. A fingerprint approval must match before it is consumed. Unknown peers cannot trigger outbound DNS.

An existing pin accepts its identical descriptor or its directly signed successor. Rotation increments generation, advances `not_before` and signs a domain-separated transcript binding both descriptors and the canonical server name with the predecessor's Ed25519 key. Only the new private seed is retained in current settings. A skipped generation or unrelated replacement requires explicit operator approval. This is an availability tradeoff for peers offline across multiple rotations; no transparency service is implemented. The public descriptor and admin responses contain no private seed.

Four discovery workers release the database before HTTPS, with durable per-peer claims, one-hour successful refresh intervals and 60-second failure backoff. Completions must match both configuration and peer revisions and the active claim. Disabled peers, failed/unapproved discoveries and pins older than an hour cannot authorize inbound requests. DNS, connect and response work is bounded by the shared egress policy; all resolved addresses are checked and pinned. Redirects, proxies and implicit private-network access are disabled. Exact host/port/CIDR exceptions may include an explicit CA while preserving TLS hostname verification. A nonstandard port requires such an exception.

The fixed v0 request profile uses [RFC 9421 HTTP Message Signatures](https://www.rfc-editor.org/rfc/rfc9421.html) and [RFC 9530 Content-Digest](https://www.rfc-editor.org/rfc/rfc9530.html). It is a restricted profile, not a general-purpose implementation accepting every RFC serialization. The ordered covered components are `@method`, `@path`, `content-type`, `content-digest`, `sigil-origin` and `sigil-destination`. Requests are POST with exact known paths, no query, JSON content type, SHA-256 body digest, 32-byte nonce and key ID, Ed25519 algorithm and the `sigil-federation-v0` tag. Signature input has one canonical parameter order. Duplicate covered headers, content encoding, unknown versions and altered method/path/body/server/parameters fail. Explicit signed destination is compared to the configured server name; untrusted forwarding headers do not select it. Outbound HTTPS separately validates the physical peer endpoint.

Ed25519 signs the signature base directly, without prehashing it. Signatures last at most 120 seconds and permit at most 30 seconds of future creation skew. After a known rotation, predecessor-key requests must have been created strictly before the new key's activation. Nonces are consumed in the same transaction as the admitted operation. Retries must use a new nonce; application-level idempotence is separate and still to be implemented for delivery. Diagnostic POST `/federation/v0/ping` accepts exactly `{}` and returns its request hash.

Admission permits a burst of 20 authenticated requests per origin, refilling one per second. Inventing extra remote accounts does not create extra origin rate budgets. Each retained nonce reserves 512 bytes against the configured 1 MiB–1 GiB peer budget and a 64 MiB global nonce budget. Maintenance deletes at most 64 expired nonces per pass and releases accounting atomically. Peer metadata separately reserves 33,792 bytes per peer against 64 MiB. Peer deletion/retirement and broader storage diagnostics are not implemented yet. These are explicit resource bounds, not claims about production capacity.

Restore disables federation, discards the local signing seed, clears nonce state and marks peer pins as requiring fresh discovery. Re-enabling generates a new key requiring explicit replacement approval at previously pinned peers. SQLite logical deletion does not guarantee physical key erasure; restored snapshots are not proof of deletion freshness.

The full workspace passes 511 tests with nine intentionally skipped; warnings-denied Clippy passes. Logs: `/tmp/sigil-federation-tls-tests.log`, `/tmp/sigil-server15-discovery-workspace.log`, `/tmp/sigil-server15-discovery-clippy.log`.

These are implementation corrections, not findings against the prior accepted backend or an independent security audit.

## Inbound mailbox increment (server schema 16)

`POST /federation/v0/deliver` accepts a canonical serialized `Submit` with sender account/device, recipient device, message ID, opaque ciphertext and an absolute expiry no more than seven days away. Signature origin supplies the remote server name. Each recipient must explicitly permit that exact server/account/device tuple. The server does not treat those transport assertions as end-to-end identity verification.

Remote deliveries share the existing mailbox's monotonic sequence, recipient quota, push transaction, acknowledgement and expiry cleanup. Local sender/device foreign-key rules remain in place for local deliveries; remote records have a distinct tagged shape. The current native local mailbox API returns local records only. `GET /client/v0/federation/mailbox?after=<sequence>` returns up to 16 remote records, including their full transport origin; the ordinary mailbox acknowledgement endpoint handles either sequence. The native cross-server encryption/session adapter is not implemented yet.

The original request hash and expiry survive acknowledgement, cleanup and restart. A fresh signed retry of the identical request returns the same receipt without restoring ciphertext. A changed body, recipient, account or expiry under the same origin/device/message ID conflicts. Admission nonce, quota, ciphertext and push enqueue commit or roll back together. At most 64 pending messages per origin and 256 total live messages per recipient are accepted, independent of how many accounts/devices the origin invents. A nonce now reserves 1 KiB; schema 16 rebuilds earlier nonce accounting. Each remote mailbox record reserves 2 KiB of retained evidence in both the origin and recipient budgets, plus its ciphertext while retained. Global remote ingress is bounded to 1 GiB. These reservations are accounting allowances, not a measurement of SQLite's physical file size.

`PUT /client/v0/federation/senders` takes a revisioned `ConfigureSender`, returning `SenderPermission`. It replaces the unversioned allow/remove API used during development. `GET /client/v0/federation/senders` lists active allowed senders; `GET /client/v0/federation/senders/{server}/{device}` reads a specific permission, including a removal tombstone. New permissions start at expected revision zero. Exact immediate retries return the same revision, while delayed requests cannot overwrite a newer decision. Accounts cannot be silently substituted for an existing remote device ID.

Permission rows reserve 2 KiB, and enabling also prepays a 512-byte revocation job. Removal therefore does not need free quota. It invalidates the current random grant ID immediately; re-enabling creates a different ID. Old queued deliveries remain invisible and cannot reappear after re-enable. Maintenance clears at most 64 revoked-grant payloads per pass, releasing the job allowance when finished. Permission tombstones and message retry evidence remain charged; they are not discarded to make room. Restore keeps that evidence, clears ciphertext through the ordinary restore path and rebuilds accounting. Old device credentials remain revoked.

Seven focused ingress tests pass: permission/receipt/nonce/push atomicity, restart and acknowledgement, maximum-size actual HTTPS delivery, native route authorization, per-origin budgets across invented accounts, bounded revocation cleanup/re-enable, restore accounting, schema-15 upgrade rollback and preservation of local receipts, and delayed permission retries. Workspace: 518 passed, nine intentionally skipped; warnings-denied Clippy passes. Logs: `/tmp/sigil-federation-ingress-tests.log`, `/tmp/sigil-server16-ingress-workspace.log`, `/tmp/sigil-server16-ingress-clippy.log`.

A test reproduced a defect in this increment's first permission API: a delayed allow could undo a later removal because requests carried no revision. Revision checks and retained tombstones replaced that API; the regression test now also covers stale removal, failed writes and quota exhaustion. The initial failed reproduction is `/tmp/sigil-federation-permission-repro.log`. This was a defect in newly written, unaccepted code, not a finding against the earlier accepted backend. Outbound delivery/retries and native interoperability remain open; item 3 is not complete.

## Outbound queue increment (server schema 17)

`POST /client/v0/federation/messages` freezes a `Queue` request before network delivery. The server derives the sender account/device from the authenticated local credential; clients cannot supply those fields. `GET /client/v0/federation/messages/{id}` returns device-scoped status. Local and federated outbound messages share the sender/message-ID namespace: changing destination, body or expiry conflicts, even after terminal completion. Local queue acceptance is not remote acceptance. Only the returned `accepted` state contains a validated remote receipt; neither state proves recipient decryption or reading.

Four bounded workers claim jobs with 45-second durable leases, release the database before HTTPS and sign the exact stored body with a fresh nonce for each attempt. Peer policy, fresh discovery pins, source-device revocation and configuration changes are rechecked. Stale leases cannot record results. A changed policy/pin defers completion to a fresh attempt. Remote receipt hash, expiry and positive sequence must match. Lost responses retry the same frozen body; no encryption operation occurs in the server queue.

Transport failures, unauthorized responses and temporary errors retain work. Backoff starts at five seconds, grows to five minutes and includes jitter. Retry-After is interpreted at response completion time. HTTP 429 and 503 also set a durable per-peer cooldown, preventing newly queued work from bypassing it while leaving other peers eligible. Malformed/conflicting/missing-target terminal responses reject the job. Jobs expire at the original deadline; revoked-source and expired work is cleared in bounded maintenance batches. An already transmitted request cannot be recalled by a later revocation or policy change.

Each source device may hold 16 pending jobs and each peer 64. Metadata reserves 2 KiB per job; the exact pending JSON body is also charged to the local account, peer resource budget and a 1 GiB global egress budget. Terminal transitions release body bytes atomically and retain charged retry evidence. Peer budgets include nonce, ingress and egress reservations. Restore marks pending jobs `restored`, discards their bodies/leases and rebuilds reservations; those jobs are never automatically retransmitted from a snapshot. Already accepted receipts remain evidence of their recorded transport outcome.

Six focused outbox tests pass, covering ambiguous delivery/restart, local receipt write rollback, stale leases/policy/device revocation, completion-time Retry-After and peer isolation, malformed receipts, message namespace conflicts, quotas/restore, real signed HTTPS delivery between two synthetic homeservers and native API authorization/body-identity rejection. Workspace: 524 passed, nine intentionally skipped; warnings-denied Clippy passes. Logs: `/tmp/sigil-federation-outbox-tests.log`, `/tmp/sigil-server17-outbox-workspace.log`, `/tmp/sigil-server17-outbox-clippy.log`.

Native cross-server identity/prekey discovery, encrypted-session/event transport integration, cross-server group/media support, peer retirement/evidence capacity policy and fuller queue/peer diagnostics remain open. The transport capability remains unadvertised; this increment does not complete item 3 or constitute an independent protocol/security audit.

## Native HTTP boundary increment

The shared native Rust HTTPS adapter now exposes revisioned permissions, queue/status inspection and remote mailbox polling. It binds outgoing status to the exact frozen request and authenticated local account/device; `pending` never becomes a fabricated delivery receipt. It rejects mismatched destinations, owners, hashes, expiries, receipt/state combinations, malformed remote origins and invalid mailbox ordering. The remote mailbox response budget accounts for sixteen maximum ciphertexts and maximum-length origin names. It continues to contact only the configured home server.

Three focused tests pass, including the actual home server over TLS and a full maximum-size mailbox response. Workspace: 527 passed, nine skipped. Optimized client: 261 passed (204 library, 57 integration), four skipped; with the unchanged explicit 1 GiB cache check, 532 distinct tests pass. Clippy passes. Logs: `/tmp/sigil-federation-client-network-tests.log`, `/tmp/sigil-federation-client-network-workspace.log`, `/tmp/sigil-federation-client-network-release.log`, `/tmp/sigil-federation-client-network-clippy.log`. The optimized run found a stale server-schema rewind fixture in the prekey lifetime test; it now drops the newly introduced tables before rewinding. The initial failure is retained in `/tmp/sigil-federation-release-fixture-before.log`. No runtime fix was required for that fixture error. Native encrypted-session routing and remote prekey discovery remain open.

## Remote lookup increment (server schema 18)

`POST /client/v0/federation/lookup` derives the authenticated local account/device and signs a bounded request to an allowed, freshly pinned peer's `/federation/v0/lookup`. Operations retrieve a client-signed device binding or claim one one-time prekey. The receiving server requires the recipient's current permission for that exact origin/account/device tuple. Server transport authentication does not establish user encryption trust.

Remote prekey assignments retain the origin, source account/device and claim request ID. Local and remote claim paths share one atomic inventory and cannot consume the same key. A fresh signed retry of the same request returns the original assignment; changing its target or account conflicts. The native HTTP adapter binds replies to the caller and exact operation, but existing cryptographic binding/signature and independently trusted identity checks remain mandatory before handshake acceptance. Durable native claim/session routing is not yet connected to this endpoint.

Four separate lookup permits remain held by actual blocking HTTPS work after an HTTP request is cancelled or times out. Network work does not hold the database lock. Completion rechecks device activity and peer/configuration revision. The existing five-second handler deadline can expire before the bounded fifteen-second HTTPS work; callers must persist and reuse claim IDs after ambiguous failures. Each new remote assignment reserves another 2 KiB against the recipient account and origin ingress budget. Expiry clears public bundle bytes while retaining assignment evidence. Restore clears bundles, preserves assignments and reconstructs those reservations.

Six server tests and one native test cover lost responses/restart, competing local and remote claims, failed writes, permission/configuration changes, restore accounting, actual HTTPS routes and malformed/substituted native replies. Workspace: **534 passed, nine skipped**. Optimized client: **262 passed, four skipped** (205 library and 57 integration); **539 distinct** including the unchanged explicit 1 GiB cache check. Warnings-denied Clippy and final lookup tests pass. Logs: `/tmp/sigil-server18-workspace.log`, `/tmp/sigil-server18-release.log`, `/tmp/sigil-server18-clippy.log`, `/tmp/sigil-server18-lookup-final.log`, `/tmp/sigil-federation-lookup-native-tests.log`. A missing field in a test-only AppState fixture and an iterator lint were corrected during validation; neither was a reproduced runtime defect. Full native cross-server session/event routing, account/device inventory, group/media integration and peer retirement remain open.

## Operator diagnostics

`GET /admin/v0/federation/status` reports global nonce, ingress, egress and peer-metadata reservations. `GET /admin/v0/federation/peers/{server}/status` reports the same peer's policy/discovery state, aggregate pending queue, retry reasons, durable cooldown and next potentially eligible attempt. Each response uses one database snapshot. Queue work is bounded by the existing 64 pending jobs per peer and reads no packet bodies or user/device identifiers. Only the Admin credential authorizes these routes; client and browser authority remain refused.

Reservations are conservative quota accounting, not measured disk use. Reducing quota below retained usage reports zero available bytes without blocking delivery of already charged work. `ready` means eligible under current recorded policy/time, not reachable or delivered. Expired, revoked and leased counts may overlap until maintenance clears terminal work. `next_attempt` is absent when policy/discovery needs work, or no pending active job could run before expiry. No probe or queue mutation is triggered by diagnostics.

All **142 server tests** and warnings-denied workspace Clippy pass, including four diagnostic tests for restart/cleanup, clock/policy/cooldown, Admin isolation, quota reduction and restore without replay. Logs: `/tmp/sigil-federation-status-server-tests.log`, `/tmp/sigil-federation-status-clippy.log`. No schema or dependency change. Native session integration and peer retirement/evidence policy remain open.
